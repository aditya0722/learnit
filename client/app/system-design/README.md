# System Design Playground

The diagram editor and simulator are available at `/system-design/playground`. `/system-design` redirects to the playground. The free and paid system design course pages and demo enrollment endpoints have been removed.

The full-page editor opens with a simple web app architecture in one data center. A compact left component library adds services; selecting a service, boundary, or connection opens its properties. File actions provide a blank canvas, the simple starter, and import/export. Run & analyze tests the current diagram. Diagrams are saved per browser, not per account or across devices. The simplified editor uses its own storage key, preserving older saved diagrams.

Connection paths show colored direction arrows and visible labels. Hover or focus a component to reveal arrow handles on its four sides. Drag a handle to another component or one of its side handles: a flowing preview snaps to a valid target, release draws the connection and briefly highlights the target. Empty-space releases, Escape, and pointer cancellation discard the draft. Self-connections and duplicate directed connections are rejected. Chosen sides are retained when moving components, reloading, importing/exporting, and sharing. Keyboard users can focus a side handle and press Enter, then focus a destination component and press Enter. Editor handles and previews are omitted from SVG exports. Dragging a component reveals a dustbin; hover over it for 450 ms or release over it to delete. A shrink animation marks removal, connected edges are removed, and Undo restores the component, its original position, and its edges. Moving away cancels the hover; Escape or a cancelled pointer gesture restores the position. Focused components can also be deleted with Delete or Backspace.

The searchable library contains 41 component types across clients, networking and security, compute, data and storage, messaging, and operations. Drag a component onto the canvas to place it at the pointer, or click/press Enter to add. Escape, a cancelled pointer gesture, or releasing outside the canvas cancels placement. Placement respects zoom and pan; Undo removes a newly added component.

Smart layout helpers work when moving components or dragging them from the library. Pink guides snap centers and footprint edges; measured gaps use canvas units. Green measurements mark equal spacing in a row or column, including insertion between two components. Snapping uses a six-screen-pixel tolerance at every zoom level. Hold Alt to bypass it temporarily, or turn off Snap in the canvas controls. Helpers are excluded from SVG exports. Validate the placement rules with `node --test test/diagram-alignment.test.cjs`.

The canvas supports dragging and keyboard positioning, renaming, directed connections, deleting, undo/redo, local persistence, JSON import/export, static SVG export, and animated connection direction. JSON imports and URL snapshots are validated and limited to 80 nodes and 160 edges. Shared links contain an immutable diagram snapshot in the URL fragment; edit and share again to produce a new snapshot. Large diagrams can be shared as JSON files. The deployed site must be reachable for recipients to open links.

Editor coordinates stay fixed as components are added, so existing services do not shift at density thresholds. The simulation view gives dense diagrams more space between service zones. Both use rounded connection routing. The simulation map occupies the full workspace with configuration underneath. Overview shows primary local connections; zone navigation focuses a single service zone, selecting a component reveals its connections, and All connections reveals the full graph. Active transfers always reveal their routes. Live counters are optional to keep idle diagrams readable. Expand opens a larger map. Use Ctrl/⌘ + scroll or the zoom buttons to zoom; normal scrolling moves the page.

The playground's **Run & analyze** mode executes the current diagram in a browser worker. Send a single request, a 25-request burst, or timed traffic at 1–100 requests per second. Configure entry points, request keys, read/write mix, deadlines, component processing times and slots, waiting limits, cache TTL, queue retries, load-balancer routing, and connection policies. Rules survive JSON export/import and snapshot sharing. The simple starter includes clients, a load balancer, services, a cache, backing storage, and a FIFO queue with a worker.

The event engine models calls and returning responses, cache hits/misses and warming, bounded service buffers, healthy-instance routing, durable queue messages, worker acknowledgements, retry backoff, dead letters, asynchronous fan-out, and explicit fallback paths. Components and links can fail manually; random outages and operation failures use a reproducible seed. Restoring workers drains preserved jobs. Synchronous routing cycles fail with a trace rather than hanging. Live metrics include foreground successes/failures, in-flight requests, average throughput over simulated time, successful-request latency percentiles, buffered messages, retries, and background tasks. Save a baseline to compare experiments and export a JSON report with rules, faults, metrics, and retained traces.

Results depend on configured assumptions and are not production benchmarks. The first version does not simulate database contents/consistency, bandwidth, CPU scheduling, or full replication. It supports 500 foreground requests and 2,000 total tasks in flight, retains 100 finished traces plus in-flight requests, and calculates percentiles from the latest 2,000 successful requests. Animation displays at most 60 simultaneous transfers; all modeled requests contribute to counts. Foreground completion does not mean background work has finished.

Run validation from `client`:

```sh
node --test test/system-design.test.cjs test/architecture-simulator.test.cjs
node node_modules/typescript/bin/tsc --noEmit
node node_modules/eslint/bin/eslint.js app/system-design components/architecture-simulation-lab.tsx lib/architecture-simulator.ts lib/architecture-simulator.worker.ts lib/system-design.ts
```

Expanded catalog types share the simulator's existing service, client, cache, database, storage, queue, worker, load-balancer, and event-bus models. For example, SQL/NoSQL databases participate in cache-aside, message brokers buffer FIFO jobs, and stream processors consume them. API gateways and security/operations blocks model configurable processing and connections; DNS protocols, security rules, rate-limit algorithms, and vendor-specific behavior are not emulated.

Usability improvements: Ctrl/Cmd+Z undoes canvas actions; Ctrl/Cmd+Shift+Z and Ctrl/Cmd+Y redo them. Text fields retain native text editing shortcuts. Name, title, and boundary edits are grouped into one undo step when the field loses focus or selection changes. Clicking empty canvas space commits the edit and dismisses properties; dragging the background still pans. The labeled File menu closes after actions. JSON export opens a preview with download and clipboard options. Simulator failures show their latest reason beside the metrics, with a direct link to the failed request trace.
